## 🔴 기-13 / 직접검증-4 — 근본 원인을 브라우저로 새로 특정했습니다

기획팀·직접검증 모두 "사진이 사라진다"는 **증상**은 맞혔지만 **원인 위치가 달랐습니다.**

### 실제로 해본 것 (1024px, 로그인 상태)
1. `/write`에 **사진 1장만** 올림 → 화면은 정상 (`1/5`, "대표" 배지 표시)
2. 이 시점에 `localStorage`를 확인 → **임시저장 키가 아예 없음**
3. ✕(닫기)를 누름 → **경고 한 번 없이** 즉시 이탈
4. `/write`로 되돌아옴 → **`0/5`, 복원 배너 없음. 사진 완전 소실**

### 원인 (두 줄이 함께 만든 문제)

```
write/page.tsx:62   useUnsavedGuard(!!(title || content))        ← images 없음 → 경고 안 뜸
write/page.tsx:114  if (!title && !content && !selectedCat) {
                      localStorage.removeItem(DRAFT_KEY);        ← 사진만 있으면 오히려 '삭제'
                      return;
                    }
```

- 기획팀 기-13(나)의 "이탈 경고 조건에 사진이 없다"는 **맞습니다** (`:62`).
- 그런데 **더 중요한 `:114`를 아무도 못 짚었습니다.** 임시저장 여부를 판단하는 조건에도
  `images`가 빠져 있어, **사진만 있는 상태는 "빈 글"로 취급되어 임시저장을 지웁니다.**
- 직접검증-4는 "용량 초과로 저장이 실패한다"고 봤지만, **용량과 무관합니다.**
  1×1픽셀 70바이트 이미지로도 똑같이 사라졌습니다. **저장 시도 자체를 안 합니다.**
- 기-13(가)(`discardDraft`에 `setImages([])` 없음)는 코드상 사실이나
  🖥️ **재현 불가** — 애초에 사진이 저장되지 않으니 복원될 것도, 지울 것도 없습니다.

**고칠 곳: `:62`와 `:114` 두 줄의 조건에 `images.length > 0`을 함께 넣으면 됩니다.**
