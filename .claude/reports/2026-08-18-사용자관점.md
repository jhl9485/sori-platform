### 기-1. 로그인하면 무조건 홈으로 — 하려던 자리로 돌아오지 못한다
- **막히는 지점**: 매물을 저장하려다 로그인했더니 그 매물이 아니라 홈에 떨어진다.
- **위치**: `lib/auth.ts:104` (어디서 왔는지 기록 안 함) · `login/page.tsx:31·36` · `signup/page.tsx:58`
- **범위**: 로그인 벽이 걸린 곳이 **6군데**(저장/답글/신고/질문/리뷰/글쓰기) 전부 같은 결말. 특히 `JobContact.tsx:38` "로그인하고 보기"는 연락처를 보려고 누른 건데 로그인 후 그 공고가 사라진다.
- **확인**: 로그아웃 → `/realty` 매물 상세 → "🏷️ 저장" → 로그인 → **홈으로 떨어지면 지적이 맞음**
- **수정 방향**: `/login?redirect=...` 로 원래 주소를 넘기고 성공 후 복귀

### 기-2. 부동산 매물에 연락할 방법이 아예 없다 — 게다가 작성 화면은 "연락처가 노출된다"고 약속한다
- **위치**: `realty/[id]/page.tsx:165` 주석 `(중개사 정보는 표시하지 않음)` — 상세 전체에 연락 항목 0개
- **거짓 약속**: `realty/write/page.tsx:575` — *"연락처는 등록 후 매물 상세 페이지에서 별도 인증 절차를 거쳐 노출됩니다."* 그런데 **작성 화면에 연락처 입력칸 자체가 없다.** 저장 구조에도 없음(`userContent.ts:202-224`)
- **왜 심각한가**: 매물 올린 사람은 연락이 올 거라 믿고 기다린다. 양쪽 다 헛수고. (벼룩은 최소한 "설명에 연락처를 적어달라"고 요구 — `flea/write:422`)
- **수정 방향**: (가) 연락처 칸 추가 + `JobContact`처럼 로그인 후 공개, (나) 당장 못 만들면 **거짓 약속 문구부터 삭제**

### 기-3. 검색 → 결과 → 상세 → 뒤로 = 검색어가 통째로 사라진다
- **위치**: `search/page.tsx:22` — 검색어·탭·결과를 어디에도 저장 안 함
- **대조**: 목록 6개는 전부 `useListRestore`로 복원한다. **이 앱은 문제를 알고 6곳을 고쳤는데 통합 검색만 빠졌다.**
- **추가**: `search/page.tsx:126` — `←`가 홈으로 고정. 채용에서 들어와도 홈으로 감
- **확인**: `/search` "EP 비자" 검색 → 결과 클릭 → 뒤로가기 → **빈 검색 화면이면 맞음** (같은 실험을 `/flea`에서 하면 제대로 돌아옴)

### 기-4. 로그인만 하면 남의 이름('김싱가해')으로 활동하게 된다
- **위치**: `lib/auth.ts:63-69` `login()`이 이름을 안 건드림 · `lib/profile.ts:15-21` 기본값이 `김싱가해 / EP / 3년차 / Tanjong Pagar` · `CommentSection.tsx:399` 댓글 작성자 = `profile.name`
- **왜 생기나**: 회원가입 경로만 이름을 세팅한다(`signup:56`). **로그인 경로엔 그 처리가 없다.** 로그인 화면에 "카카오/구글로 시작하기"가 크게 있어 상당수가 로그인 경로로 들어온다.
- **결과**: 입력한 적 없는 이름으로 글·댓글이 등록된다
- **수정 방향**: 로그인 후 이름이 기본값이면 닉네임을 한 번 묻는 단계. 최소한 기본값을 사람 이름이 아닌 것으로

### 기-5. 저장 공간이 꽉 차면 조용히 실패하는데 화면은 "저장했어요"라고 말한다
- **위치**: `lib/storage.ts:24-26` — 실패를 통째로 삼키고, 실패해도 `setIds(next)` 실행(`:51`) → 화면상 성공처럼 보임 · `DetailActions.tsx:52` 무조건 토스트

- **수정 방향**: `storage.ts`의 `write`가 성공/실패를 반환하게 하고 실패 시 같은 문구로 안내

### 기-6. 오류 화면이 없는 메뉴를 안내한다 — 따라가면 내 글이 전부 지워진다

## ✅ 잘 되어 있는 것 (유지해야 할 기준)

1. **삭제 앞에는 항상 확인창** — 내 글·상세·댓글·질문·거래상태 전부. "되돌릴 수 없어요" 명시
2. **전체 초기화는 2단계 확인** — 무엇이 지워지는지 목록으로 보여준 뒤 한 번 더 물음
3. **작성 중 자동 임시저장 + 복원 배너** — 5개 작성 화면 전부
4. **저장 공간 부족 시 사진을 빼고 저장하고 알린다** — 글을 통째로 잃지 않게 하는 훌륭한 처리
5. **검색 결과 0건 화면** — 검색어를 되짚고 추천 검색어 제시. 한 탭만 비면 "전체 결과 보기 →"
6. **404·에러 화면에 나갈 길이 여러 개**
7. **로그인이 필요한 *이유*를 설명** — "무분별한 수집·스팸을 막기 위한 조치예요" (`JobContact:34-37`). 로그인 벽의 모범
8. **게스트에게 막기 전에 미리 알림** — 댓글창이 아예 "🔒 로그인하고 댓글 남기기"로 바뀜. **눌러본 뒤 튕기는 것보다 훨씬 낫다**
9. **로그인 없이 둘러볼 수 있고 그렇게 말해준다**
10. **목록 6곳이 뒤로가기 시 필터·스크롤 복원** (검색만 빠짐 = 기-3)
11. **마감·판매완료를 상세 맨 위에서 명확히 알림**
12. **미인증 업소 경고와 거래 안전 안내** — "선입금 요구 시 사기 위험이 있습니다"
13. **불러오는 중·실패 상태 표시** — LiveBar, 스켈레톤
14. **개인정보 처리방침이 솔직하다**
15. **새 댓글 작성 후 그 자리로 스크롤 + 강조** — "내가 쓴 게 어디 갔지"를 없앰
16. **뉴스 상세 끝에 관련 기사 + 목록 링크** — 상세 6종 중 유일하게 끝에서 다음 행동을 제시

## ⚪ 확인하지 못한 것

1. **실제 브라우저 실행 검증** — 코드만 읽음. 확인 순서대로 해봤을 때 설명과 다르면 **그 지적이 틀린 것**
2. **실기기 모바일 동작** — 한 손 조작 거리, 키보드 가림은 실제 폰에서만 확인 가능. 기-22는 코드상 위치만 근거
3. **숫자·데이터 정합성** — 데이터팀 담당, 중복 회피
4. **모양·색·크기 일관성** — 디자인팀 담당. 기-22·23은 "모양"이 아니라 "길을 못 찾는 문제"로 한정
5. **뉴스·커뮤니티 본문 내용** — 범위 밖
6. **데스크탑 우측 패널** — 참고용으로만 훑음
7. **`jobs/write` `business/write` 전문** — 필수항목·임시저장·이탈경고만 확인
